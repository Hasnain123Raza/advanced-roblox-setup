# Advanced Roblox Setup

A Roblox game template that treats the game like a real software project.

You write the game in **TypeScript** — compiled to Luau by [roblox-ts](https://roblox-ts.com) and synced into Studio by [Rojo](https://rojo.space). Studio-authored content, assets, and configuration live in git too. Every change passes a strict set of quality gates — formatting, linting, typing, documentation, dependencies, secrets — and the test suite runs inside a real Roblox server, not a mock.

This repository is a starting point, not a framework: clone it, connect Rojo, and the next commit is your game.

## What you get

- **TypeScript, not Luau.** Strict, type-aware, linted game code in `src/` — 100% type coverage is enforced, so no `any` slips through.
- **Everything in git.** Game code, Studio content, assets, and configuration all round-trip through the repository; Studio consumes git, it is not the source of truth.
- **Typed assets.** Drop files in `assets/`, run one command, and [Asphalt](https://github.com/jackTabsCode/asphalt) uploads them and generates typed asset IDs to import.
- **Gates on every change.** Prettier, ESLint, StyLua, selene, luau-lsp, CSpell, Knip, TypeDoc, gitleaks — enforced by git hooks locally and by CI.
- **Tests in the engine.** [Jest Lua](https://jsdotlua.github.io/jest-lua/) specs run inside a real Roblox server through Open Cloud Luau execution.
- **CI/CD to Roblox.** GitHub Actions runs every gate, runs the in-engine tests, and on `main` publishes the built place with [rbxcloud](https://github.com/Sleitnick/rbxcloud).

## Quick start

You need [mise](https://mise.jdx.dev) and Roblox Studio with the Rojo plugin.

```sh
mise install        # Node and every CLI tool, pinned with checksums
npm install         # packages and git hooks
npm run setup       # Lune editor type definitions
cp .env.example .env
npm run roblox:docs # local clone of the Roblox creator docs (engine reference)
```

Then, in two terminals:

```sh
npm run watch   # recompile TypeScript on save
npm run serve   # sync into Studio through the Rojo plugin
```

Open the place in Studio — the sample scripts in `src/client` and `src/server` greet you when you play.

## How it fits together

```text
src/client/     TypeScript -> StarterPlayerScripts.TS   (client)
src/server/     TypeScript -> ServerScriptService.TS    (server)
src/shared/     TypeScript -> ReplicatedStorage.TS      (both)
  __tests__/    Jest specs, included in the test place only
  assets/       Generated by Asphalt; import from here, never edit
place/          Studio-authored content, saved by `npm run place:fetch`
assets/         Source files Asphalt uploads (images, audio, ...)
lune/           Tooling scripts in Luau (place fetch, tests, analysis)
tasks/          Luau that runs inside Roblox (the Jest bootstrap)
docs/           The game's documentation: big picture, design, progress
```

`default.project.json` describes the game; `test.project.json` is the same game plus the specs and the test harness.

## Day-to-day

**Studio content.** Build it in Studio, then save it into the repository:

```sh
npm run place:fetch                        # the place in ROBLOX_PLACE_ID (.env)
npm run place:fetch -- --place-id 123456   # a specific place
npm run place:fetch -- --file my.rbxl      # a local file, no login needed
```

By default it captures the children of the `Models` folders under `ReplicatedStorage` and `ServerStorage`, one `.rbxm` per child, and the entire `Workspace`, `Lighting`, and `TextChatService` services as `place/<Service>.rbxm`; whole-service capture of other services is opt-in, and AGENTS.md explains how to onboard a service.

**Assets.** Put files in `assets/`, set `ASPHALT_API_KEY`, and run `npm run assets:sync`. Commit the new files, `asphalt.lock.toml`, and the generated `src/shared/assets/` together.

**Tests.** Specs live next to the code (`src/**/__tests__/*.spec.ts`) and import from `@rbxts/jest-globals`. `npm test` uploads the test place and runs the specs inside a real Roblox server.

**Verify.** `npm run check` runs every local gate — the same set CI runs, minus the in-engine tests.

## CI/CD

On every pull request and push to `main`: every gate, a build of `game.rbxl`, a secret scan of the full history, a dependency review, the in-engine tests — and on `main`, a publish to Roblox. A second workflow can publish the API docs to GitHub Pages.

Configuring it (repository variables, secrets, the test experience) is documented in AGENTS.md.
